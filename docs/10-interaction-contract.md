# 10 · 交互契约与 GUI 验收

本文约定用户可观察的行为，不指定 GUI 技术栈或视觉风格。接口以 [08](08-api-contract.md) 和 [OpenAPI](../api/openapi.yaml) 为准；下面的场景完成联调前不冻结 v1。

## 1. 导航与首次使用

- 主导航围绕工作区；选定工作区后显示当前会话及终端、产物、服务。桌面只在能力可用时提供，凭证/MCP/审计放在管理入口；不要直接把后端资源列表做成十个同级页面。
- 首次流程：连接 Codex → 安装 → 创建或选择工作区 → 启动。GitHub/MCP 按需连接，可跳过；凭证失效时就近提供重新连接入口，保留当前工作区上下文。
- 会话头部始终可辨认工作区、harness、运行状态及网络模式。打开产物/服务后能回到同一终端，不新建任务。
- 选择已有目录时展示规范化路径、读写权限和“直接修改原文件”；说明 `.env` 等自带凭证不在 Nullkey 凭证隔离保证内。

## 2. 操作与反馈

| 场景 | 行为与反馈 |
|---|---|
| 点击启动 | 立即显示已接收；区分准备中、连接终端、终端可输入；收到 WS `ready` 后启用输入 |
| 关闭终端视图 | 断开显示连接，后台任务继续；“停止沙箱”是独立操作 |
| 重开/刷新/断线 | 接回同一 PTY，触发 TUI 重绘；显示历史输出不能恢复的提示；不重放用户输入 |
| daemon 重启 | 显示原任务已中断；允许用已有工作区/会话状态新启动，不伪装成原进程恢复 |
| 安装中 | 显示阶段和实际进度；取消后先显示清理中，收到 `cancelled` 才显示已取消 |
| OAuth 中 | 显示等待浏览器授权，提供取消和重试；取消成功后迟到回调不能建立连接 |
| 网络被拒绝 | 显示被拒绝的目标与模式；不自动切换 `open`；`services_only` 明示模型/MCP/git 仍联网 |
| 凭证检查完成 | 显示“生成配置/环境未发现注册凭证”、范围、排除项和时间；不声称整个项目可安全分享 |
| 工作区被占用 | 显示占用会话和前往入口；不暗中停止它，不删除其文件 |
| 本机身份验证 | 真实模式的解锁、凭证变更和敏感操作调用 macOS 系统认证；取消、认证不可用或桥接失败时停止操作，保持原状态，不降级为演示验证 |

停止/删除沙箱始终保留数据。清除会话说明会失去配置、历史和会话；删除 managed 工作区文件说明会失去整个目录（含 `.git` 和未提交文件），展示路径并要求输入名称。external 工作区只提供“从列表移除”。具体规则见 [07](07-state-and-mounts.md#7-重置与清理)。

## 3. 键盘、文本与动态效果

- 全流程可用键盘完成，焦点始终可见。提供离开终端的应用快捷键（默认 `Cmd+Shift+M` 聚焦工作区导航），在快捷键帮助中可发现，避免依赖会被 TUI 消费的 Tab/Escape。
- 菜单/对话框打开时合理移入焦点，关闭后回到触发控件；错误提示与对应操作关联，状态变化可由 VoiceOver 读取，不用持续播报覆盖每个终端输出片段。
- 使用系统字体和可调整终端字号；200% 文本缩放下主操作、取消按钮和错误信息仍可见可用。读写权限、运行状态和错误不能仅靠颜色表达。
- 按下控件立即反馈；等待后端期间保持导航和取消入口可用。进入/退出方向一致，动画可中断，不能等待动画结束才接收下一次操作。
- 跟随系统减少动态效果、降低透明度和提高对比度设置：分别使用静态/短淡入淡出、实色背景及清晰边界。动效、半透明材质和阴影不承担唯一的状态提示。

## 4. 联调验收

- [ ] 未连接 GitHub 也能首次进入 Codex；授权失败后可在原上下文重试。
- [ ] 安装中取消不会留下半安装版本；重复取消和“完成同时取消”显示服务器实际结果。
- [ ] OAuth 取消后再提交旧回调不会保存凭证；已完成授权的取消返回冲突并显示已连接。
- [ ] 关闭/刷新/重开终端后 PID 和 `terminal_id` 不变，原任务继续，TUI 重绘可用；新窗口替换旧写连接，输入不重复。
- [ ] daemon 重启后明确显示任务中断；workspace/state 仍可用于新启动。
- [ ] 停止/删除沙箱保留 workspace/state；外部目录删除文件被拒绝；活动资源清理被拒绝；managed 删除前显示具体路径和范围。
- [ ] 三种网络模式均明确 gateway 的联网行为；无法执行策略时拒绝启动，不静默降级。
- [ ] 自带 `.env` 的项目不会被标记为“整个项目无秘密”；检查错误不会被展示为零命中。
- [ ] 键盘可进入并离开终端、完成授权/取消/确认；焦点恢复正确；VoiceOver 能读出状态和错误。
- [ ] 200% 文本缩放和三种系统辅助显示设置下操作可用；连续操作不会被动画锁住。
- [ ] 按 [SLO](../slo.md) 测量 POST → WS ready → 输入启用，另报 harness 就绪时间与失败次数。

## Codex ChatGPT 登录（issue #8）

- 宿主已有 `auth_mode=chatgpt` 登录时，导入后 GUI 的 `expires_at` 非空，来源是
  access token JWT 的 `exp`；refresh/id token 与 account id 由宿主保存，不展示。
- 首次连接也可以直接用“用 ChatGPT 登录”：daemon 使用 Codex 公开 client，注册的
  回调固定为 `http://localhost:1455/auth/callback`，只在登录期间监听；1455 被
  Codex CLI 登录占用时明确提示，不静默换端口。
- 沙箱内 Codex 无需再次登录：`~/.codex/config.toml` 由 daemon 渲染，只引用
  `NULLKEY_TOKEN` 和本地 gateway；用户不应看到 `codex login`。
- Codex 使用 `https://127.0.0.1:<gateway>/openai`，并由 `CODEX_CA_CERTIFICATE`
  信任 Nullkey 本地 CA；CA 不进入系统钥匙串/信任库。
- 网关按导入的 account id 注入 `ChatGPT-Account-Id`；沙箱无法切换账号。
- 同时有 OpenAI API key 和 ChatGPT 登录时，Codex 优先使用 ChatGPT 登录；只有
  撤销该登录后才使用 API key。
- Codex 的插件/应用与共享 daemon 在 v1 沙箱内默认关闭；终端启动不再等待
  app-server 探测或 WebSocket 回退。
- 凭证过期前 gateway 自动刷新；刷新失败时返回 `reauth_required`，不把旧 token
  发往第三方，也不降级直连。
