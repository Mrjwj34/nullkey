# 14 · 桌面端 UI/UX 原型规范

> 适用范围：Nullkey macOS 桌面客户端 v1 原型与视觉验收。
>
> 本文只定义 GUI 的信息架构、视觉语言与交互表现，不修改
> [`api/openapi.yaml`](../api/openapi.yaml) 的语义。实现以
> [API 契约](08-api-contract.md) 与 [交互契约](10-interaction-contract.md) 为准。
>
> 视觉令牌的单一真相见
> [`design-system/nullkey/MASTER.md`](../design-system/nullkey/MASTER.md)。本文定义页面、
> 流程与原型验收；组件实现不得在页面内另建一套颜色、间距或动效值。

## 1. 设计目标

Nullkey 是给日常使用编码 Agent 的桌面工具，不是安全专家的策略控制台。界面首先要让用户快速回到项目并开始工作，同时持续、准确地表达安全边界。

### 1.1 体验目标

1. 首次使用在 5 分钟内进入可输入的 Codex TUI。
2. 日常打开应用后，用户在一次点击内继续最近工作区。
3. 用户始终知道自己在哪个工作区、运行什么 harness、沙箱是否运行、使用哪种网络模式。
4. 凭证连接、失效和重连发生在宿主侧；任何沙箱内界面都不要求输入真实凭证。
5. 停止任务、清除会话、移除工作区和删除文件必须在语言与操作层级上明显不同。
6. 安全状态具体、可核验、不夸大。不得使用“绝对安全”“项目无密钥”“完全离线”等文案。

### 1.2 设计原则

- **工作优先**：终端是主工作面，安全控制围绕任务出现，不占据主舞台。
- **安静可信**：克制的 macOS 工具风格，信息密度适中，避免营销式大标题、渐变和装饰卡片。
- **就近恢复**：凭证失效、网络拒绝、工作区锁定等问题在当前上下文内给出修复入口。
- **状态可辨**：颜色只作辅助，图标、标签和文本共同表达状态。
- **危险分级**：停止进程与删除数据不能共享同一视觉权重或确认方式。
- **失败关闭可见**：策略执行失败时明确阻止启动，不提供“仍然继续”或自动切换开放网络的入口。

### 1.3 UI/UX Pro Max 设计旋钮

| 旋钮 | 值 | 对原型的约束 |
|---|---:|---|
| Variance | 3/10 | 构图稳定、居中、可预测，不用实验性导航 |
| Motion | 2/10 | 动效仅表达反馈和空间关系，不做装饰性入场 |
| Density | 8/10 | 面向重复工作的紧凑桌面布局，但保留清晰分组 |

风格采用 **macOS 原生工具感 + 克制的 Swiss Minimalism**。UI/UX Pro Max 的自动匹配中，
“高对比、语义令牌、低动效、清晰焦点”适用于本产品；FAQ 落地页、全局等宽字体、霓虹黑客风与
滚动揭示不符合桌面工作台情景，明确不采用。

## 2. 用户与核心情景

### 2.1 主要用户

- 使用 Codex、Claude Code 或 DSH 的个人开发者。
- 熟悉终端和项目目录，但不想配置代理、YAML 或凭证注入。
- 关心 key 泄漏风险，不一定理解 gateway、Seatbelt 或 OAuth PKCE。
- 主要设备为 macOS Apple Silicon，常在 13–16 英寸笔记本上长时间使用。

### 2.2 核心情景

| 优先级 | 情景 | 用户目标 | 设计响应 |
|---|---|---|---|
| P0 | 首次连接 Codex | 不在终端粘贴 key，尽快开始 | 引导式设置，默认 OAuth，API key 为备选 |
| P0 | 继续最近项目 | 找回上下文并直接工作 | Home 首位显示最近工作区与“继续” |
| P0 | 运行编码 Agent | 稳定使用 TUI，不被 GUI 干扰 | 终端占据工作台主体；输入仅在 WS `ready` 后启用 |
| P0 | 处理连接失效 | 修复凭证后继续当前任务 | 会话内横幅提供“重新连接”，保留工作区上下文 |
| P1 | 审查 Agent 产物 | 在不修改文件的前提下看文件与 diff | 会话内 Artifacts 视图，只读并清楚标注截断 |
| P1 | 打开 WebUI/preview | 访问沙箱声明服务 | Services 列表显示健康状态，通过一次性 ticket 打开 |
| P1 | 调查网络拒绝 | 知道什么被阻止以及为什么 | 就地提示目标与当前模式，可前往设置但不自动放宽 |
| P1 | 停止或清理 | 停进程但保留工作，或明确删除数据 | 三层操作语义与不同确认强度 |

## 3. 信息架构

### 3.1 全局结构

采用“工作区 → 当前会话 → 工作视图”的三级结构，不把后端资源映射为十个同级页面。

```text
Nullkey
├── 工作区
│   ├── 最近使用
│   ├── 全部工作区
│   └── 当前会话
│       ├── 终端（默认）
│       ├── 产物
│       ├── 服务
│       └── 桌面（能力可用时）
└── 管理
    ├── 连接（凭证 + MCP）
    ├── 活动与审计
    └── 设置
```

### 3.2 导航模型

- 左侧边栏宽 248 px，承载工作区、最近项和管理入口。
- 顶部会话栏高 52 px，承载当前上下文和运行控制。
- 会话内分段导航使用 `终端 / 产物 / 服务 / 桌面`，不另开新的全局层级。
- “桌面”仅在 `desktop_available=true` 时显示；不可用时不放置永久禁用标签。
- 设置、连接与审计使用主内容区，不使用多层浮动卡片。

### 3.3 页面清单

| 页面 | 主要任务 | 主操作 |
|---|---|---|
| Home / 工作区 | 继续、新建、导入工作区 | 继续工作、新建工作区 |
| 首次设置 | 连接 Codex、安装 harness、建立工作区 | 继续、启动 |
| 会话工作台 | 使用终端、切换产物与服务 | 启动 / 停止 |
| 工作区详情 | 查看路径、权限、状态和历史会话 | 启动新会话 |
| 连接 | 管理模型凭证与 MCP | 连接、测试、撤销 |
| 活动与审计 | 解释启动、凭证、网络、服务事件 | 筛选、导出 |
| 设置 | 默认网络、资源、终端与辅助选项 | 保存 |

## 4. 应用框架

### 4.1 窗口与尺寸

- 推荐原型画板：1440 × 900 px。
- 最小支持窗口：1024 × 700 px。
- 默认窗口：1280 × 820 px，记忆用户上次尺寸与位置。
- 标题栏遵循 macOS traffic lights 安全区；工具栏内容不进入左上 80 px。
- 窗口小于 1120 px 时，左侧边栏可收为 64 px 图标栏；终端不得小于 640 × 420 px。
- 不设计移动端；窄窗口通过折叠次要信息，不把桌面布局重排成手机卡片流。

### 4.2 会话头部

左到右固定顺序：

1. 工作区名称与外部/托管标识。
2. Harness 名称与版本。
3. 运行状态。
4. 网络模式按钮。
5. 弹性空白。
6. 资源摘要（CPU / 内存，可选折叠）。
7. 主运行控制。
8. 更多菜单。

启动中的按钮显示 spinner 与“正在启动”；收到终端 `ready` 前，终端输入区保持只读。停止按钮使用中性色，只有真正删除数据的操作使用危险色。

### 4.3 工作台布局

- 主内容默认全宽终端，终端外不套装饰卡片。
- 右侧检查器宽 320 px，用于网络拒绝详情、文件信息、服务详情等临时上下文；默认关闭。
- 底部状态栏高 28 px，显示连接状态、终端字号、当前路径和 request ID 入口；不显示 token 或任何凭证值。
- 终端、产物和服务共享同一会话头，不因切换视图创建新沙箱。

## 5. 视觉语言

### 5.1 风格定位

视觉关键词：**安静、精确、本地、可控**。

采用浅色和深色双主题，默认跟随系统，不强制深色。整体接近专业开发工具而非消费级 VPN：边界清晰、留白克制、局部高密度；避免大面积纯蓝、紫色渐变、玻璃拟态、霓虹“黑客”风和悬浮大卡片。

### 5.2 色彩令牌

颜色需通过 WCAG 2.2 AA；以下为浅色主题基准，深色主题按语义映射而非简单反色。

| Token | 色值 | 用途 |
|---|---|---|
| `bg.canvas` | `#F5F6F7` | 应用背景 |
| `bg.surface` | `#FFFFFF` | 面板、菜单、对话框 |
| `bg.subtle` | `#ECEFF1` | 选中前悬停、分组底色 |
| `text.primary` | `#171A1D` | 正文与标题 |
| `text.secondary` | `#515B65` | 辅助信息，正文对比度不低于 4.5:1 |
| `border.default` | `#D2D8DD` | 分隔线与输入框 |
| `accent.primary` | `#176B5B` | 主操作、焦点、当前项 |
| `accent.hover` | `#125548` | 主操作悬停 |
| `status.success` | `#147A52` | 已连接、运行中 |
| `status.warning` | `#A35A00` | 风险提示、开放网络 |
| `status.danger` | `#B4232D` | 删除、失败、撤销 |
| `status.info` | `#2864A8` | 准备中、一般提示 |
| `terminal.bg` | `#111416` | 终端背景 |
| `terminal.fg` | `#E7EAEC` | 终端前景 |

深色主题基准：`bg.canvas #15181A`、`bg.surface #1D2124`、`bg.subtle #292F33`、`text.primary #F1F3F4`、`text.secondary #C1C8CD`、`border.default #3C444A`、`accent.primary #54B7A0`。深色主题独立验对比度，不从浅色主题直接反色。

网络模式不使用单色等级误导安全性：

- 仅允许已连接服务：链环图标 + 中性蓝灰。
- 限定网站：滤网图标 + 主强调绿。
- 开放网站：地球图标 + 警示琥珀色。

### 5.3 字体

- UI：`SF Pro Text` / 系统字体；不增加网络字体依赖。
- 代码、路径、request ID：`SF Mono`。
- 终端：用户可选等宽字体，默认 `SF Mono`；等宽字体不扩散到普通界面正文。
- 页面标题 20/28 semibold；分区标题 15/20 semibold；正文 13/20 regular；辅助文字 12/16 regular。
- 不使用随视口变化的字体尺寸；字距为 0。
- 终端字号默认 13 px，可在 10–24 px 调整。

### 5.4 间距、圆角与层级

- 4 px 基础网格；常用间距 8 / 12 / 16 / 24 / 32。
- 控件高度：小 28 px、默认 32 px、引导主操作 36 px。
- 圆角：输入框与按钮 6 px；菜单、对话框、重复项容器 8 px；状态胶囊 999 px。
- 页面分区以分隔线和间距组织，不把每个区块包装成浮动卡片。
- 阴影只用于菜单、popover 和 modal；固定页面面板无阴影。

### 5.5 图标与动效

- 使用一致的 16/18 px 线性图标集；按钮优先使用熟悉图标并提供 tooltip。
- 运行状态可使用静态圆点；不要用持续脉冲制造焦虑。
- 按压/悬停 80 ms；同容器内容替换 120 ms 淡入；检查器进入 160 ms、退出 100 ms；弹窗 120 ms 淡入。
- 跟随“减少动态效果”时仅保留不超过 100 ms 的淡入淡出。
- 动画不能阻塞输入、取消或导航。
- 动画中断时直接设置最终语义状态；实现正确性不得依赖 `animationend` 或 `transitionend`。

## 6. 核心页面规范

### 6.1 Home / 工作区

**目标**：用户打开应用后立即继续工作。

布局：

- 顶部 56 px 标题区：`工作区`，右侧“新建工作区”。
- 最近使用采用紧凑列表，每行 64 px；最多显示 6 条。
- 行内容：名称、规范化路径、最近使用时间、上次 harness、锁状态。
- 行操作：主要是“继续”；悬停后出现更多菜单。
- 无最近项时显示简洁空状态与两个操作：“创建托管工作区”“选择已有目录”。

规则：

- 已被 rw 会话占用时显示“正在使用”，主操作为“前往会话”。
- 外部目录显示 `外部` 标签和真实路径，不暗示 Nullkey 管理文件生命周期。
- 托管目录显示 `托管` 标签，但删除文件仍必须显式确认。
- 不在 Home 暴露 state、sandbox ID 等实现概念。

### 6.2 首次设置

使用单窗口、四步线性流程；左侧显示步骤，右侧显示当前任务。允许返回，但完成 OAuth 或安装后不重复执行。

#### 步骤 1：连接 Codex

- 默认主操作：“使用浏览器连接”。
- 次操作：“使用 API key”。
- API key 输入为 password field，只在提交请求体内使用；不提供显示、复制或保存到剪贴板按钮。
- OAuth 状态：等待浏览器、已连接、已取消、授权失败、需要重试。
- 等待授权时保留“取消”；取消进入“正在取消”，服务端确认后才显示已取消。

#### 步骤 2：安装 Codex

- 显示版本、来源、校验状态、下载与安装阶段。
- 进度条使用实际 `progress`；未知进度用 indeterminate，不伪造百分比。
- 取消后显示“正在清理”；只有 job 状态为 `cancelled` 后返回上一步。

#### 步骤 3：选择工作区

- 首选两个大行选项而非卡片墙：“创建托管工作区”“选择已有目录”。
- 已有目录确认页必须展示规范化完整路径、`读写` 权限和“将直接修改原文件”。
- 固定提醒：项目自带的 `.env`、密钥文件及用户主动输入不在 Nullkey 凭证隔离保证内。

#### 步骤 4：启动

- Harness 默认 Codex，网络默认“限定网站”。
- 网络选项使用单选列表，并在每项下写清 gateway 行为。
- “仅允许已连接服务”文案：关闭通用网站访问；模型、MCP 和私有 Git 仍可通过已连接服务联网。
- “开放网站”选项展示非阻断式风险说明，不预选。

### 6.3 会话终端

**目标**：让 TUI 成为稳定、可持续的主工作面。

- `starting`：终端区域显示分阶段状态“正在准备沙箱 → 正在连接终端”；不显示假终端 prompt。
- WebSocket open 但未收到 `ready`：输入禁用，状态为“终端尚未就绪”。
- `ready`：聚焦终端并启用输入；首次启动可自动聚焦，重连不抢走用户在其他控件的焦点。
- 关闭窗口或切换页面仅 detach，不显示“任务已停止”。
- 重连成功后显示一次性通知：“已接回运行中的终端。断开期间的历史输出无法恢复。”
- 新窗口替换旧写连接时，旧窗口显示只读遮罩：“终端已在另一窗口接管”。
- daemon 重启后显示中断页：“原进程已结束。工作区与会话数据仍保留。”主操作为“重新启动”。

终端工具栏：复制、搜索、清屏、字号减小/增大、全屏；使用图标与 tooltip。清屏仅清当前渲染缓冲，不描述为删除历史或 state。

### 6.4 产物

三栏布局：文件树 240 px、内容/差异主区、自适应信息检查器。

- 默认打开“更改”视图，按文件列出 diff；可切换“文件”。
- 只读标识固定在标题栏，不提供编辑器式保存按钮。
- 二进制文件给出类型、大小与“无法预览”，不尝试执行。
- 内容超过 1 MiB 时显示“预览已截断”，并展示已加载范围。
- symlink 或路径越界错误使用明确文案：“该路径位于工作区之外，已阻止访问。”
- 非 Git 目录的空 diff 显示“未检测到可展示的文件差异”，不是错误。

### 6.5 服务

- 使用表格/列表，列为名称、协议、状态、健康检查、端口（可在详情显示）、操作。
- 健康服务主操作为“打开”；获取 ticket 期间禁用重复点击。
- 服务崩溃但终端仍可用时，显示局部错误，不升级为整个会话失败。
- 未声明服务不能手工输入端口打开；界面不提供任意端口转发入口。
- tunnel 失效时重新获取 ticket，不要求用户复制本地 URL。

### 6.6 连接（凭证与 MCP）

同一管理页分为“模型与代码托管”和“MCP”两个分区。

凭证行只显示 provider、标签、认证方式、fingerprint、状态和过期时间；永不显示、复制或导出明文。

状态与操作：

| 状态 | 显示 | 主操作 |
|---|---|---|
| 未连接 | 未连接 | 连接 |
| 连接中 | 等待浏览器授权 | 取消 |
| 已连接 | 已连接 · fingerprint | 测试连接 |
| 即将过期 | 即将过期 | 重新连接 |
| 需要授权 | 需要重新授权 | 重新连接 |
| 测试失败 | 连接测试失败 | 查看详情 / 重试 |
| 已撤销 | 已撤销 | 重新连接 |

撤销凭证需要普通确认，文案明确：“所有使用该连接的沙箱将在下一次请求时失败。”确认框不展示任何 secret。

MCP 行显示服务名、认证来源、允许工具数、连接状态；工具 allowlist 放在详情抽屉中。未知 server 或工具被拒绝时不建议回退到默认上游。

### 6.7 活动与审计

- 默认按时间倒序，采用紧凑表格，不使用事件卡片流。
- 筛选：时间、工作区/会话、类型、结果。
- 事件类型：沙箱启动/停止、凭证添加/撤销、OAuth、网络拒绝、服务打开/关闭。
- 列：时间、事件、对象、结果、摘要；详情在右侧检查器打开。
- 网络拒绝显示 host/SNI、模式、状态与 request ID；不显示 query string、header、body、Cookie 或 Authorization。
- 导出前提示导出内容已脱敏，但不得宣称用户项目或终端内容无秘密。

### 6.8 设置

分组顺序：默认行为、网络、终端、存储、辅助功能、关于。

- 网络默认值为“限定网站”。更改默认值不影响已运行沙箱。
- “开放网站”使用 warning callout，说明数据可通过通用网络外发；不是凭证隔离失效。
- 不提供名为“离线”的开关。
- Desktop capability 不可用时，用说明行展示“当前版本未提供桌面运行时”，不显示可操作假开关。

## 7. 组件规范

### 7.1 按钮层级

| 类型 | 用途 | 示例 |
|---|---|---|
| Primary | 页面唯一主要推进动作 | 启动、连接、继续 |
| Secondary | 并列但非主路径 | 选择目录、测试连接 |
| Ghost / Icon | 工具操作 | 搜索、全屏、更多 |
| Danger | 不可逆数据删除 | 删除托管工作区文件 |

每个可见区最多一个 Primary。停止沙箱不是 Danger；撤销凭证可在确认框中使用 Danger；删除文件必须使用 Danger。

异步按钮保持原宽度，使用前置 spinner 与 `busy` 状态，阻止重复提交；取消必须是独立可操作控件，不能因为主按钮 loading 而消失。Hover/pressed 只改变颜色、透明度或边界，不做导致布局跳动的位移或缩放。

### 7.2 状态标签

固定词汇：`准备中`、`运行中`、`已停止`、`启动失败`、`正在取消`、`已取消`、`已连接`、`需要授权`、`访问被拒绝`。

标签必须包含文字；圆点或图标不能单独表示状态。状态变化通过 `aria-live=polite` / macOS accessibility announcement 播报，终端每一行输出不播报。

状态 badge 是静态信息，不得因为胶囊外观就变成可点击控件。筛选 chip、切换按钮和状态 badge 必须使用各自正确的语义。

### 7.3 通知

- Toast 用于操作已接收、复制成功、非阻断完成，最长显示 6 秒。
- Banner 用于需要在当前上下文修复的问题，如凭证失效、终端断线。
- Inline error 紧邻输入或动作。
- Modal 只用于确认高风险操作或阻止当前流程的问题。
- 错误详情可展开显示 request ID；默认不暴露内部错误字符串。

### 7.4 空状态与骨架屏

- 空状态说明“目前没有什么”以及唯一下一步，不写产品宣传语。
- 首屏数据加载使用与真实行结构一致的 skeleton，最长约 1 秒后显示进度或错误。
- 刷新现有列表时保留旧内容并显示局部进度，不让整个页面闪白。

## 8. 网络模式交互

| 模式 | 显示名称 | 一句话说明 | 使用提示 |
|---|---|---|---|
| `services_only` | 仅允许已连接服务 | 关闭通用网站访问；模型、MCP、私有 Git 仍可联网 | 不得标为离线 |
| `filtered` | 限定网站 | 允许已连接服务和批准的网站 | 默认推荐 |
| `open` | 开放网站 | 允许通用网站访问，凭证仍由 gateway 管理 | 显示数据外发风险 |

网络被拒绝时：

1. 在终端上方显示非遮挡 banner。
2. 显示被拒绝的目标和当前模式。
3. 提供“查看活动详情”和“网络设置”。
4. 不提供一键“改为开放并重试”，不自动改变策略。

## 9. 删除与确认模型

### 9.1 停止沙箱

- 结果：停止进程、撤销当前 token；保留 workspace 与 state。
- 确认：运行中任务存在时使用普通确认；无数据删除警示色。
- 文案：“停止后当前进程会结束，工作区文件和会话数据会保留。”

### 9.2 删除沙箱记录

- 结果：停止沙箱并删除记录；始终保留 workspace 与 state。
- 不显示 `delete_state` 或 `delete_workspace` 选项。

### 9.3 清除或删除 state

- Reset：清除配置、历史与会话，保留 state 记录。
- Delete：删除 state 目录与记录。
- 两者都明确“不影响工作区文件”，且活动会话占用时禁用并提供前往入口。

### 9.4 移除工作区

- External：仅“从列表移除”，明确磁盘文件保持不变。
- Managed 默认：仅移除记录并保留文件。
- Managed 删除文件：显示完整路径、`.git`、未提交与未跟踪文件均会删除；要求输入工作区名称；确认按钮文案为“永久删除文件”。
- 活动沙箱占用时不允许操作，不暗中停止会话。

## 10. 凭证检查结果

结果页固定包含：

- 结论：“生成配置和环境中未发现已注册凭证”或具体失败。
- 范围：`generated_runtime`。
- 排除项：工作区、用户导入文件、用户主动输入。
- 检查时间。
- 命中数或错误状态。

禁止文案：

- “项目中没有密钥”
- “可以安全分享整个目录”
- “100% 无泄漏”

检查失败时显示“检查未完成”，不能显示 0 命中或成功图标。

## 11. 错误映射

| API code | 用户标题 | 恢复动作 |
|---|---|---|
| `unauthorized` | Nullkey 连接已失效 | 重新连接本地服务 |
| `state_locked` | 工作区正在使用 | 前往占用会话 / 以只读方式打开（可用时） |
| `reauth_required` | 需要重新连接账户 | 在当前上下文重新连接 |
| `runtime_unavailable` | 无法启动安全沙箱 | 查看诊断；不提供无沙箱继续 |
| `desktop_unavailable` | 当前未提供桌面运行时 | 返回终端 |
| `network_denied` | 网络访问已被当前模式阻止 | 查看目标 / 网络设置 |
| `terminal_not_ready` | 终端尚未就绪 | 自动退避重试，保留取消入口 |
| `ticket_invalid` | 连接已过期 | 自动申请新 ticket 后重试一次 |
| `service_not_found` | 服务不可用或未声明 | 返回服务列表 |
| `conflict` | 操作与当前状态冲突 | 刷新实际状态，不宣称操作成功 |
| `job_failed` | 操作未完成 | 查看阶段与重试 |
| `internal` | Nullkey 遇到问题 | 显示 request ID 与重试 |

所有错误正文使用后端稳定错误码映射，不直接显示内部错误；详情区保留 request ID 供诊断。

## 12. 键盘与无障碍

- 全流程可键盘完成，焦点环至少 2 px，和背景对比不低于 3:1。
- `Cmd+Shift+M`：离开终端并聚焦工作区导航。
- `Cmd+1/2/3/4`：切换终端、产物、服务、桌面（存在时）。
- `Cmd+,`：设置；`Cmd+K`：全局工作区切换器。
- 不覆盖 harness/TUI 的常用快捷键；应用级快捷键需在帮助菜单中可发现。
- 对话框打开后聚焦标题或首个安全操作；关闭后回到触发控件。
- 200% 文本缩放下，主操作、取消和错误信息不能被裁切；路径可中间截断并通过 tooltip/复制查看完整值。
- 跟随减少透明度、提高对比度与减少动态效果系统设置。
- 所有图标按钮有可访问名称；状态、权限和风险不只靠颜色表达。
- 固定会话栏、banner、底部状态栏和终端遮罩不能完全遮住键盘焦点；焦点进入被遮挡区域前必须滚动、移动或关闭遮挡层。
- 列表达到 50 行以上时可虚拟化，但返回页面必须恢复滚动位置、筛选条件和当前键盘焦点。

## 13. 原型画板清单

高保真原型至少包含以下 18 个画板；每个画板同时标注正常、hover、focus、disabled 和错误状态。

1. Home：有最近工作区。
2. Home：首次空状态。
3. 首次设置：Codex 连接方式。
4. 首次设置：OAuth 等待与取消中。
5. 首次设置：安装进度与清理中。
6. 首次设置：选择外部目录并展示边界。
7. 首次设置：网络模式与启动摘要。
8. 会话：正在启动。
9. 会话：终端 ready。
10. 会话：断线重连与历史不可恢复提示。
11. 会话：daemon 重启后的中断恢复。
12. 产物：文件树与 diff。
13. 服务：健康、启动中、失败混合状态。
14. 连接：凭证与 MCP 列表。
15. 凭证：需要重新授权的就地恢复。
16. 活动与审计：网络拒绝详情。
17. 工作区：managed 永久删除确认。
18. 凭证检查：成功范围与检查失败。

关键可点击路径：

```text
首次打开
  → 连接 Codex
  → 安装
  → 选择工作区
  → 选择网络模式
  → 启动
  → 终端 ready

再次打开
  → 最近工作区
  → 继续
  → 原会话上下文

网络被拒绝
  → 会话 banner
  → 活动详情
  → 网络设置
  → 用户显式保存

凭证失效
  → 会话 banner
  → 宿主浏览器重新授权
  → 返回同一会话
```

## 14. 内容规范

- 使用“工作区”“会话”“终端”“连接”，避免向普通用户暴露 `sandbox`、`state`、`gateway`、`ticket` 等内部词；诊断详情可显示技术术语。
- 操作按钮使用动词：`继续工作`、`启动`、`停止`、`重新连接`、`从列表移除`。
- 不用“重置工作区”；v1 没有此语义。
- “仅允许已连接服务”必须伴随“模型、MCP、私有 Git 仍可联网”的解释。
- 不将 Seatbelt 描述为 VM 级隔离，不宣称阻止恶意 Agent 或 prompt injection。
- 外部工作区固定说明：“Nullkey 会直接修改此目录。目录内已有凭证不受 Nullkey 凭证隔离保证覆盖。”

## 15. 验收标准

原型评审通过需满足：

- 首次路径在不连接 GitHub/MCP 的情况下可进入 Codex。
- 任意会话页都能辨认工作区、harness、运行状态和网络模式。
- 终端只有在 `ready` 后可输入；关闭视图不等于停止任务。
- 三种网络模式都准确说明 gateway 仍联网，且不存在“离线”误导。
- 任何凭证视图都不出现明文、复制或 reveal 能力。
- 停止、删除记录、清除 state、删除工作区文件具有明确不同的文案和确认强度。
- 凭证检查展示范围、排除项和时间，失败不伪装为零命中。
- 1024 × 700 和 1440 × 900 下无文本或控件重叠；200% 文本缩放可完成主路径。
- 键盘能进入和离开终端、完成 OAuth 取消、错误恢复与危险确认。
- 减少动态效果、降低透明度和提高对比度下仍能分辨所有状态。

GUI 团队交付应包含：
