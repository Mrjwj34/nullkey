# Nullkey 产品演示视频脚本

## 制作规格

- **总时长：** 2 分钟
- **语言：** 中文旁白与中文屏幕文字
- **产品名称：** `Nullkey`，始终保留英文，不翻译
- **画幅：** 1920×1080，16:9
- **开场形式：** 纯代码 2D 画布动效
- **产品展示：** GUI 原型、终端、架构动效与安全验证
- **数据口径：** 只使用测试凭证、示例项目和模拟授权状态

## 核心主张

> Agent 获得完成工作的能力，真实凭证留在你的 Mac。

Nullkey 管理的真实 API key、OAuth token 和 password 保存在宿主 Keychain。沙箱只获得绑定当前环境、可以撤销的 per-sandbox token；模型、MCP 和私有 Git 请求由宿主 Gateway 完成真实认证。

## 完整旁白

> 如果你的 AI 编程 Agent 能使用 API key，却从来没有见过它，会怎样？
>
> 我们通常把 API key 和 OAuth token，直接交给 AI 编程 Agent。但它们可能进入环境变量、配置、日志和项目文件。当会话被分享或备份，一次普通的信息泄漏，就可能带走长期凭证。
>
> Nullkey 改变的，是凭证进入 Agent 的方式。真实 API key 和 OAuth token 保存在宿主 Keychain。沙箱里只有一枚绑定当前环境、可以随时撤销的临时 token。只有请求经过宿主 Gateway 时，真实凭证才会在沙箱之外完成注入。
>
> 使用 Nullkey，不需要先编写代理配置，也不需要在沙箱里填写密钥。选择工作区、Agent、会话状态和网络模式，然后启动。默认的 Filtered 模式只允许经过批准的通用网络目标。
>
> Nullkey 使用轻量的 macOS 原生进程沙箱，不需要先启动虚拟机。终端就绪后，就可以像平时一样使用 Codex。关闭终端视图不会停止后台任务。重新打开时，Nullkey 会连接回同一个运行环境。
>
> 模型、MCP 和私有 Git 的认证请求，都由宿主 Gateway 处理。Agent 可以使用这些能力，却拿不到真实凭证。沙箱内声明的 Web 服务可以通过本机隧道打开；生成的文件和 diff 可以集中审查；活动记录只保留必要的请求元数据。
>
> 最后，直接检查沙箱环境和 Nullkey 生成的配置。这里没有已注册的真实凭证，只有当前沙箱使用的临时 token。停止沙箱，这枚 token 立即失效；项目文件和会话状态仍然保留。
>
> Agent 获得完成工作的能力，真实凭证留在你的 Mac。Nullkey，让 Agent 工作，不把钥匙交给它。

## 安全与表述边界

- 不说“Nullkey 完全防止 Agent 泄漏数据”。
- 不说“Nullkey 防御 prompt injection”。
- 不说“Nullkey 提供 VM 级隔离”。
- 不把 `services_only` 说成离线模式；三种网络模式都保留 Gateway 联网能力。
- 不把凭证检查说成整个项目绝对无密钥。
- 检查结果必须注明范围是 Nullkey 生成的运行环境和配置。
- 用户项目中的 `.env`、导入文件和主动粘贴内容不在 Nullkey 管理凭证的保证范围内。
- 视频素材只使用 `sk-test-*`、假 OAuth 状态和示例项目，不使用真实凭证。
