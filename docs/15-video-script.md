## 完整旁白

> Nullkey。
>
> 如果 Agent 能使用 API key，却看不到它？
>
> 能使用，但看不到。
>
> 我们通常把 API key 和 OAuth token，直接交给 AI 编程 Agent。但真实凭证一旦进入运行环境，就可能被写入更多会话材料。
>
> 这些内容可能被分享、备份或用于排查问题。一次普通的会话泄漏，就可能变成长期凭证泄漏。
>
> Nullkey 改变的，是凭证进入 Agent 的方式。真实 API key 和 OAuth token 保存在宿主 Keychain。
>
> 沙箱里只有一枚绑定当前环境、可以随时撤销的临时 token。只有请求经过宿主 Gateway 时，真实凭证才会在沙箱之外完成注入。
>
> 这意味着，Agent 可以完成工作，却不会在自己的环境、配置或会话里拿到 Nullkey 管理的真实凭证。
>
> 使用 Nullkey，不需要先编写代理配置，也不需要在沙箱里填写密钥。选择工作区、Agent、会话状态和网络模式，然后启动。默认的 Filtered 模式只允许经过批准的通用网络目标。
>
> Nullkey 使用轻量的 macOS 原生进程沙箱，不需要先启动虚拟机。终端就绪后，就可以像平时一样使用 Codex。关闭终端视图不会停止后台任务。重新打开时，Nullkey 会连接回同一个运行环境。
>
> 模型、MCP 和私有 Git 的认证请求，都由宿主 Gateway 处理。Agent 可以使用这些能力，却拿不到真实凭证。
>
> 沙箱内声明的 Web 服务可以通过本机隧道打开；生成的文件和 diff 可以集中审查；活动记录只保留必要的请求元数据。
>
> 最后，直接检查生成环境。这里没有已注册的真实凭证，只有当前沙箱使用的临时 token。
>
> Nullkey，让 Agent 工作，不把钥匙交给它。

## 表述边界

- 说“Nullkey 管理的真实凭证不进入沙箱”。
- 不说“Nullkey 防止所有数据泄漏”。
- 不说“Nullkey 防御 prompt injection”。
- 不说“Nullkey 提供 VM 级隔离”。
- 不把 `services_only` 说成离线模式。
- 不把凭证检查扩大为“整个项目没有密钥”。
- 检查结果只覆盖 Nullkey 生成的运行环境与配置。
- 视频只使用测试凭证、示例项目和模拟状态。
