# Nullkey GUI 第二轮方案

状态：第二轮交互原型已落地，待团队评审。入口 `index.html` 转到 `v2.html`，实现位于 `v2.js` / `v2.css`。当前为独立 mock，不连接真实 daemon。第一轮 preview.png 为历史截图。

依据：[产品范围](../docs/00-product.md)、[状态与挂载](../docs/07-state-and-mounts.md)、[API 契约](../docs/08-api-contract.md)。本文的布局、用户文案、默认选中规则是 GUI 提案，不改变后端契约。

## 1. 本轮目标与审查处理

用户在任意操作前都能回答：正在看哪个项目、哪一次运行、使用哪个 Agent、操作会影响什么。先用多项目样例验证结构，再补首次使用与故障流程，最后完善视觉。

| 审查项 | 性质 | 处理 |
|---|---|---|
| 工作区显示运行/停止、没有沙箱身份 | 与资源模型不一致 | 删除工作区自身运行状态；运行标记必须带关联 sandbox |
| 所有页面同层导航 | GUI 结构问题 | 分为全局、工作区、沙箱三个范围 |
| 新建项目覆盖旧名称 | 原型模型缺陷 | 用独立资源集合与 ID，新增不修改旧资源 |
| OAuth/API key、目录、安装异常未完成 | 设计缺项 | 第二阶段补齐，不将占位页误报为后端缺陷 |
| GitHub、state 选择未完成 | 设计缺项及部分契约待确认 | 补流程；state 恢复承诺受 harness 能力限制 |
| Terminal 仿聊天 | 容易误导实现 | 明确 TUI 容器边界，移除应用自建聊天输入与回复 |
| 授权过期禁用终端、失败仍展示成功记录 | 状态设计错误 | 分离 sandbox、terminal、credential 三套状态 |

## 2. 对象模型与文案规则

| 对象 | ID / 数据来源 | 生命周期与归属 | 对用户的表达 |
|---|---|---|---|
| 工作区 workspace | ws_*；/workspaces | 持久项目目录，可关联多次 sandbox 记录 | 名称、路径、最近使用、关联运行数量 |
| 沙箱 sandbox | sbx_*；/sandboxes | 一次 Agent 运行环境，引用 workspace、state、harness | 简短 ID、Agent、生命周期、网络、启动时间 |
| Agent 工具 harness | /harnesses | 全局安装资源；每次启动选择受支持工具 | Codex、安装状态、固定版本 |
| 会话状态 state | st_*；/states | harness 配置与历史，可被后续运行复用；不是 sandbox 子对象 | 新建状态 / 复用已有状态；展示 ID 与来源 |
| 终端连接 | sandbox terminal endpoint / WS | 某个 sandbox 的客户端连接状态 | 连接中、已连接、已断开、进程已退出 |
| 凭证 credential | cred_*；/credentials | 全局连接；可能被多个 sandbox 使用 | 已连接、已过期、已撤销 |

工作区可有多次运行记录；文件与 diff 属于整个工作区，并非某次运行的快照。state 按 harness 管理，可能跨工作区使用，不能凭 workspace ID 推导 state 所有权。

术语固定：“新建工作区”创建项目资源；“启动 Agent”创建运行环境；“打开终端”连接已有 sandbox；“停止沙箱”停止指定运行；“复用会话状态”保留配置/历史。只有确认 harness 支持并成功恢复后，才显示“对话已恢复”。

不得使用：“工作区运行中”“启动工作区”“会话已保留所以对话必然恢复”。工作区卡片可写“关联沙箱：1 个运行中”，归属必须清楚。

## 3. 导航与布局

```text
全局侧栏
  首页
  工作区（可搜索列表、添加）
    个人网站
    文档站
    API 服务
  全局管理
    凭证 / MCP 连接 / 活动记录 / 设置

选中工作区后的内容区
  工作区名称 + 项目路径
  工作区页签：文件与产物 | 运行记录
  运行选择器：Codex · sbx_web_02 · 运行中
  沙箱页签：Terminal | Services | 运行详情
```

运行选择器与工作区页签是两个范围：先选项目，才允许选择该项目的 sandbox。布局可直接展开当前运行，不要求用户逐层进入。页面顶部始终保留“工作区 / sandbox 短 ID / Agent”，窄窗口也不得隐藏这三个身份。

全局首页分三块：Agent 工具及安装状态、最近工作区、正在运行的沙箱。运行卡片明确展示 workspace 名称与 sandbox ID，可一键连接已有终端。

进入已有工作区：存在运行中 sandbox 时优先选中该项目最近查看的有效运行；有多个时显示选择器。无运行时显示项目概览与启动按钮。应用启动优先恢复上次有效位置，无可恢复位置时进入首页；首次进入引导。切换项目不触发启动或停止，也不修改原项目状态。

运行记录由 sandbox 列表按 workspace_id 关联生成；不是单独虚构的 history API。记录删除后不承诺仍有完整历史，持久审计与 sandbox 记录保留期需确认。

## 4. 工作区主动作

| 场景 | 主动作 | 实际行为 |
|---|---|---|
| 没有运行且没有历史 | 启动 Agent | 打开启动面板 |
| 存在运行中 sandbox | 打开终端 | 申请该 sandbox 的 terminal ticket，不创建新 sandbox |
| 多个可访问的运行 | 打开终端 + 运行选择器 | 明确选中 ID；无选择时先选运行 |
| 上次运行已停止 | 继续工作 | 打开启动面板，解释将创建新沙箱；可复用旧 state |
| workspace/state 被占用 | 查看占用环境 | 显示 locked_by；仍可查看文件，停止动作需显式选择 |
| 上次启动失败 | 查看原因，重试 | 显示错误；重试重新走创建流程，不伪造终端输出 |
| 正在启动/停止 | 显示阶段 | 禁用同一对象的重复操作，不阻止切换项目 |

同一工作区默认只有一个 rw 使用者，不能通过“再开一个”绕过锁。多个项目可各有运行；同项目 ro 共享与 state 复制作为 Should，须能力与后端支持后再开放。

停止按钮位于 sandbox 工具栏，文案/提示明确“停止 Codex · sbx_web_02”；点击后仅更新这个 ID。停止成功后说明该沙箱访问令牌失效，工作区与 state 保留。第一轮不加入批量停止与删除。

## 5. 启动面板与首次使用

启动面板标题：“为「个人网站」启动 Agent”。摘要持续显示项目路径、Agent、网络和 state 选择。

1. 选择项目：导入已有目录，或创建 Nullkey 管理的新目录。名称与 root_path 分开；取消目录选择不创建资源；路径错误贴近字段显示。原型用明确标注的模拟目录选择，不读取用户磁盘。
2. 选择 Agent：来自 harnesses，Codex 为首选；Claude Code / DSH 依 capabilities 和安装清单显示，未支持项不伪装可启动。未安装时进入安装任务，覆盖 queued/running/succeeded/failed、未知进度与重试。
3. 连接凭证：Codex OAuth 或 API key；GitHub OAuth / PAT 对应 MCP 连接流程。首次使用清楚显示 GitHub 尚未连接，可明确选择稍后设置；团队交付验收仍须跑通真实 GitHub MCP。不要阻止用户在模型已就绪时先进入本地工作。
4. 选择会话状态：新建 state，或选择与 harness 匹配的已有 state。优先展示由历史 sandbox 明确关联的状态；其他兼容 state 放在展开列表，不能默认为该项目独占所有。新 state 不删除旧 state。提示“复用配置与历史；对话恢复取决于 Agent 支持”。
5. 选择网络：默认 filtered；services_only/open 均解释影响。三种模式保留网关联网，services_only 不是离线。运行中网络编辑接口未定义，当前配置只读。
6. 确认摘要后提交，经历 creating/starting/running，再申请 terminal ticket。失败停留在该次运行详情，可查看原因并重试。

OAuth 画面：选择方式 → 打开宿主浏览器 → pending → succeeded / failed / expired → 重试。API key / PAT 画面：宿主表单、遮罩输入、必填校验、保存中、保存失败、连接测试、成功摘要；不回显明文。交互原型仅用假值示例，不接收/保存真实凭证。

多凭证绑定、MCP 与 sandbox 的绑定字段尚未明确：设计展示全局连接状态与可用性，但不承诺“为此沙箱切换账号”已可调用。首次使用设计完成后，需与后端确认启动前的账号选择规则。

## 6. Terminal 与三套独立状态

Nullkey 管理顶部工具栏：项目/运行身份、连接状态、复制选区、全屏、重新连接、运行详情、停止。中间是 harness 的 TUI 容器，输入和快捷键交给终端；不放应用自建的“发送消息”按钮。

状态示例：“沙箱运行中 · 终端已断开 · Codex 账号已连接”。三者分别订阅/查询，不用一个 running 布尔值联动。

| 变化 | Terminal 行为 | 沙箱行为 / 恢复 |
|---|---|---|
| OAuth 过期 | 本地终端输入仍可用；显示模型授权提示 | 不改变 sandbox 状态；宿主重授权，不自动重放请求 |
| WebSocket 断开 | 保留已收到的缓冲画面，明确离线，不发送输入 | 查询 sandbox；仍运行则重新申请 ticket |
| ticket 过期 | 无须让用户复制令牌 | 重新申请；不创建新 sandbox |
| 沙箱启动失败 | 展示空终端或诊断画面，不放历史成功记录 | 显示 last_error，重试创建流程 |
| 沙箱已停止 | 此运行输入关闭；旧输出仅作为客户端已缓存内容 | 创建新运行前确认 state；不将旧 ID 改回 running |
| 网络被阻止 | 显示目标与原因；本地终端仍可用 | 不自动改成 open；活动记录关联 sandbox |
| daemon 离线 | 显示“运行状态未知”；保留内容 | 不推断进程退出，服务恢复后重新查询 |

全屏保留退出入口与身份；尺寸变化对应 resize 消息；复制只复制选区，不自动读写剪贴板。重连输出是否重放依后端协议，不能承诺无丢失回放。TUI 内 shell/Agent 仍有自身输入状态，GUI 不保证每条本地输入都被 harness 接受。

## 7. 第二轮原型的数据与样例

原型数据用资源集合：workspaces、sandboxes、states、harnesses、credentials、jobs、oauth_flows。导航状态分别持有 selected_workspace_id、selected_sandbox_id；terminal_connections 与输出缓冲按 sandbox_id 保存。提交/授权状态按资源或任务 ID 保存，不能用全局 scenario 改写所有项目。

必须内置的评审样例：

| 工作区 | 关联运行 | 验证点 |
|---|---|---|
| 个人网站 ws_web | sbx_web_02 运行中；sbx_web_01 已停止，引用 st_web | 当前终端与历史区分，停止指向当前 ID |
| 文档站 ws_docs | sbx_docs_01 运行中，终端断开 | 切换项目不停止其他运行；重连不新建 |
| API 服务 ws_api | sbx_api_01 失败，无 TUI 输出 | 失败画面、原因与重试 |
| 新建项目 | 无运行，独立新 ID | 新建不会覆盖已有项目 |

这些 ID 为 GUI 假数据。多运行指跨项目并行；同工作区的两个示例是不同时间运行，不违反 rw 独占。额外锁冲突场景显示占用的具体运行，不能凭全局锁定开关修改所有项目。

## 8. 分阶段交付与通过标准

| 顺序 | 交付 | 必须通过才能进入下一步 |
|---|---|---|
| P0 对象与结构 | 多工作区低保真原型；运行切换器；历史详情；按 ID 停止 | 用户能指出项目与沙箱；打开终端不创建运行；新建不覆盖；切换后各自状态保留 |
| P1 主流程 | 目录选择；Agent 安装；OAuth/API key；GitHub 连接；state 选择；创建进度 | 首次流程完整；失败/过期可重试；不能承诺必然恢复对话 |
| P2 终端与异常 | TUI 容器；复制/全屏/resize；三套状态；断线与授权恢复 | OAuth 失效不封锁终端；重连不重建；启动失败无假记录；停止期间防重复 |
| P3 辅助与视觉 | 文件/diff；Services；活动过滤；间距与响应式 | 所有数据明确归属；按 capabilities 开关 Should；键盘与小窗口可识别当前对象 |

以评审通过条件排序，不继续沿用“三天把所有页面画完”的排期。P0 先稳定信息架构，不再以颜色和装饰作为本轮完成标准。P1/P2 的表单与状态图可在 P0 评审期间准备，但高保真布局依 P0 结果统一。

## 9. 与后端需确认的契约

| 问题 | 文档现状 | 设计的处理 |
|---|---|---|
| 已停止运行如何继续 | 无 start/resume endpoint；POST /sandboxes 可引用 workspace/state | 暂设计为创建新 sandbox，保留原记录；与后端确认 |
| 选择账号、provider、MCP 绑定 | 创建 sandbox 字段未明确这些关系 | 标为待定，不实现虚构绑定请求 |
| 可恢复哪个 harness 对话 | state 有配置/历史，没有会话列表或 resume 能力字段 | 不提供具体对话选择，待能力与接口确认 |
| 运行记录长期保留 | 可列出 sandbox，可删除 | 展示现存记录；不承诺永久历史或历史输出 |
| 生命周期 | 状态机含 creating/stopping，例子字段枚举较少 | 与后端/OpenAPI 对齐完整枚举及重连后的状态查询 |
| 窗口重开与输出重放 | 已明确同一 PTY；ready 后输入；不保存服务器 scrollback；新连接替换旧连接 | attach 同一 terminal_id；不重放输入；提示历史不可恢复；terminal_replaced 后停止自动重连 |
| state 占用与项目关联 | 默认独占；列表按 harness 过滤 | 从 sandbox 关系辅助定位；提交以 409 为准 |
| 凭证失效影响哪些运行 | 全局凭证，绑定字段未定义 | 不声称知道精确受影响列表，等待关联契约 |
| 设置、allowlist | 保存/修改接口未定义 | 仅展示现状，不提供假保存 |

安装与 OAuth 取消接口已定义。原型覆盖安装 cancelling → cancelled，以及 OAuth cancelled 后旧结果不生效；手动模拟结果便于逐状态评审。

## 11. 本轮实现边界与评审入口

- 多工作区、独立 sandbox 集合、运行记录、项目文件与沙箱终端分层已实现；新建项目不会覆盖现有项目。
- 启动经历 creating → starting → running → terminal connecting → ready；停止经历 stopping → stopped。异步回调按具体 sandbox 对象执行，切换项目不会更新错误运行。
- Codex 为样例唯一可用工具；其他工具显示不可选。启动按 harness 选择兼容 state，检测活动 state 和 workspace 独占锁。
- 原型终端为明确标注的 TUI 画布，不执行输入，不提供自建聊天回复。真实 xterm.js、resize/SIGWINCH、中文输入法、200% 缩放和 VoiceOver 联调仍需在前端实施阶段验证。
- 工作区支持托管目录和模拟外部目录；外部目录明确读写权限、直接修改原文件与 .env 边界。
- OAuth 提供手动成功/失败/过期/取消；API key/PAT 仅使用只读假值模拟保存与测试，未实现真实密钥输入，也未连接 Keychain。
- 文件/diff 是按工作区区分的只读样例；Services 是按 sandbox 区分的声明服务示例与 ticket 过期/重新申请流程，不代表真实服务已启动。
- daemon 重启场景当前模拟对账完成后的 stopped，不模拟对账中的未知状态。删除/清理已补齐 mock 管理流程，见 CONTRACT-COVERAGE.md；真实 OAuth 浏览器跳转、安装真实进度和多账号绑定仍待联调。
- 导航、表单和 dialog 使用原生键盘行为；提供 Cmd+Shift+M 与可见焦点、状态播报、减少动态效果/提高对比度样式。生产辅助功能验收尚未完成。

## 10. 下一次评审脚本

1. 同时查看个人网站与文档站，说明哪个项目、哪个 sandbox 正在运行。
2. 从文档站进入 Terminal，再回个人网站；原运行数量和输出归属不变。
3. 停止 sbx_web_02，确认 sbx_docs_01 不受影响，项目文件仍可查看。
4. 对已停止记录点击继续，说明新 sandbox 与旧 state 的关系，不期待旧进程复活。
5. 新建第四个项目，返回前三个项目，确认资源未被覆盖。
6. 在运行中让账号过期，确认本地终端与运行状态没有被误改。
7. 查看启动失败记录，确认没有暗示 Agent 已执行工作的输出。
8. 触发锁冲突，能进入占用运行详情，而非无上下文地报“项目被占用”。

验收以对象理解和动作正确为主：不停止错误沙箱、不重复创建、不覆盖项目、不虚报恢复成功。尚未实现的 Services、diff 等单列待办，不混入一致性缺陷。
